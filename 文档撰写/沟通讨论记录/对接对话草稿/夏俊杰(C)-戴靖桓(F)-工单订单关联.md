# 夏俊杰（C）与戴靖桓（F）：工单订单关联

> 草稿性质：根据模块职责和现有支持/交易边界整理，用于后续沟通记录排版；不是逐字聊天记录。
>
> 参与成员：夏俊杰（C：零售交易）、戴靖桓（F：支持与运营）

## 讨论：工单如何关联订单

**戴靖桓（F）：** 我这边用户提交咨询或者售后工单的时候，想让他可以选一个相关订单。这个订单信息我是直接从订单表查吗？

**夏俊杰（C）：** 最好从我这里拿。订单有用户归属，如果直接按订单 ID 查，还得注意不能让用户看到别人的订单。

**戴靖桓（F）：** 那我传当前用户和订单 ID，你帮我判断是不是他的？

**夏俊杰（C）：** 可以。我给你必要的订单信息就行，比如订单号、状态这些。

**戴靖桓（F）：** 工单里要不要把整份订单信息复制下来？

**夏俊杰（C）：** 没必要。保存订单关联和你工单真正需要的少量信息就够了，订单本身还是我这里维护。

**戴靖桓（F）：** 那后台客服看工单的时候，再根据这个关联去看订单现在是什么状态。

**夏俊杰（C）：** 对，这样不会出现两份订单数据对不上。

## 讨论结论

F 的工单可以关联 C 的订单，但不直接复制完整订单业务数据。C 提供订单归属判断和必要的只读信息，F 保存订单关联用于客服处理。
