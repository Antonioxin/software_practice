\Needspace{10\baselineskip}
\subsection{验证方法与证据}\label{sec:52-验证方法与证据}

\begin{enumerate}
\item {\bfseries 测试}：通过自动化接口测试、脚本或界面测试校验正常、异常、边界、重复及并发行为，记录预期与实际结果。
\item {\bfseries 业务场景验证}：按 UC-01 至 UC-03 执行完整操作，核对用户反馈、后台处理结果与业务记录。
\item {\bfseries 检查}：审阅界面、接口说明、运行配置和交付文档，确认身份边界、敏感字段、发布范围及可部署性。
\item {\bfseries 分析}：根据状态表、库存变动和订单金额核对数据一致性及统计口径，使用测试结果提供证据。
\end{enumerate}

每份验证记录应包含需求编号、TC 编号、软件版本、环境、执行时间、预期结果、实际结果、通过状态、缺陷编号及证据位置。证据包括接口响应、界面截图、库存与状态记录或测量结果，应脱敏保存。详细验证场景见附录 A。

\subsection{版本验收标准}\label{sec:54-版本验收标准}

\begin{enumerate}
\item FR-01 至 FR-32 已实现，且关联的接口、数据、BR 和 NFR 要求在约定环境满足。
\item 附录 A 全部场景执行并保存结果；关键权限、金额、重复付款、库存竞争、取消和发货冲突不存在未修复缺陷。
\item UC-01 至 UC-03 可以从业务发起执行至处理结果，不依赖手工修改数据库；失败和关闭分支符合状态约束。
\item 测试失败应形成缺陷记录，修复后复测；执行记录和证据能够追溯到对应软件版本。
\item 模拟交易标识清楚，支付、退款和发货结果不触发真实外部操作；正式公开内容经业务负责人确认。
\item 安装、初始化、运行与测试命令经执行验证，已保存数据在服务重启后保留；测试重置与业务数据隔离。
\item 变更后的规格、接口说明、实现和验证记录保持一致。P1、P2 候选项不得被计入本版本已交付功能。
\end{enumerate}
