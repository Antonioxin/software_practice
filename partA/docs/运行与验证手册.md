# 运行与验证手册

## 1. 环境要求

- JDK 21、Maven 3.9+
- Node.js 20+、npm 10+
- 本机 MySQL 8.0+

不要提交真实密码或 `.env`。本地配置从 `.env.example` 复制，管理员密码至少使用 12 位随机字符串。

## 2. 本地运行

先使用本机 MySQL 管理员账户执行一次初始化（把示例密码替换为本地强密码）：

```sql
CREATE DATABASE IF NOT EXISTS wemove
    CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'wemove_app'@'127.0.0.1'
    IDENTIFIED BY 'replace-with-a-local-password';
GRANT ALL PRIVILEGES ON wemove.* TO 'wemove_app'@'127.0.0.1';
```

可通过 `mysql -u root -p` 进入客户端后粘贴上述 SQL。随后在 `partA` 下执行：

```bash
cp .env.example .env
# 编辑 .env，填写刚创建的 MySQL 密码和管理员初始密码
set -a
. ./.env
set +a
cd backend
mvn spring-boot:run
```

另开终端：

```bash
cd partA/frontend
npm ci
npm run dev
```

访问 `http://localhost:5173/register`。若 `.env` 配置了 `BOOTSTRAP_ADMIN_EMAIL` 与 `BOOTSTRAP_ADMIN_PASSWORD`，后端首次启动会创建管理员；生产环境应改为受控的离线初始化流程。

## 3. 自动验证

```bash
cd partA/backend
mvn verify

cd ../frontend
npm ci
npm run test
npm run build
```

后端测试覆盖账户初始状态、状态转换和登录/注册限流边界；前端测试覆盖状态徽标的可访问文本。生产构建会同时执行 Vue TypeScript 类型检查。

配置好本地 MySQL 与管理员环境变量后，可执行完整接口冒烟：

```bash
cd partA
export SMOKE_ADMIN_EMAIL="$BOOTSTRAP_ADMIN_EMAIL"
export SMOKE_ADMIN_PASSWORD="$BOOTSTRAP_ADMIN_PASSWORD"
bash scripts/mysql-api-smoke.sh
```

脚本使用临时 Cookie 和随机测试邮箱，验证注册、登录、资料持久化、管理员停用/恢复以及旧会话撤销。它会留下测试账户和状态历史，建议仅对开发/验收数据库执行。

## 4. 手工验收主路径

1. 打开注册页，确认未勾选成人声明/两项说明时无法成功注册。
2. 使用有效邮箱、2—30 字符昵称、8—64 位且含字母和数字的密码完成注册。
3. 登录后进入个人资料页；修改昵称与电话，刷新页面确认数据持久化。
4. 在第二个浏览器登录管理员，按邮箱找到该用户并进入详情。
5. 填写原因并停用账户；原用户下一次请求应返回 401，旧会话不能继续使用。
6. 管理员恢复账户；原会话仍然无效，用户必须重新登录。
7. 连续发送同一 `Idempotency-Key` 和同一命令，应得到相同结果且响应含 `Idempotency-Replayed: true`；同一键换请求内容应返回 409。
8. 用普通用户直接访问 `/api/v1/admin/users`，应返回 403；省略写请求的 Origin 或 CSRF，应返回 403。

## 5. 常见问题

- `Connection refused: 3306`：确认本机 MySQL 服务已启动并监听 `127.0.0.1:3306`。
- `Access denied for user`：核对 `.env` 的用户名、密码和账户主机是否为 `127.0.0.1`。
- `Unknown database 'wemove'`：先执行本手册的建库 SQL；Flyway 负责表结构，不负责创建数据库本身。
- `ORIGIN_DENIED`：把真实前端源加入 `ALLOWED_ORIGINS`，精确到协议、主机和端口，不要使用 `*`。
- `Invalid CSRF Token`：先 GET `/api/v1/auth/csrf`，保留 Cookie，并在写请求发送返回的 Header。
- 登录后立即失效：检查 Cookie 是否被浏览器拦截；HTTP 本地环境使用 `SESSION_COOKIE_SECURE=false`，HTTPS 部署必须为 `true`。
- 迁移校验失败：不要直接修改已执行的 `V1`，新增按顺序编号的 Flyway 迁移。

## 6. 生产前检查

- HTTPS、`SESSION_COOKIE_SECURE=true`、强数据库密码和受控管理员初始化。
- 将内存限流替换为共享限流实现，并配置反向代理传递可信客户端地址。
- 配置日志脱敏、数据库备份、Session/幂等记录清理和审计端口。
- 限制数据库账户权限，启用依赖漏洞扫描。
- 运行契约测试、并发状态变更测试、键盘操作和主流浏览器回归。
