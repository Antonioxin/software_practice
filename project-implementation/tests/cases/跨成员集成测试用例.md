## 1. 通用准备

- 使用独立测试库、文件目录和合成账户；业务状态由初始化脚本及公开业务操作产生，不手改数据库制造已付款或已审批状态。只读查询可用于核对结果。
- U1、U2 是两个普通用户，DA、DB 是两家企业的有效经销商主账户，ADM 是管理员。除 T-I-03、T-I-06 明确改变资格外，每例独立恢复前置数据。
- P1、P2 是已上架商品，零售价分别为 2990、5900 分，初始库存各 10。询价专用 Q1 已启用经销、配置完整，最小询价量 12，库存 5。商品及文件均标注“测试”。
- 写操作携带各自身份、有效 CSRF 令牌、所需版本；每个新逻辑操作使用新 UUID 幂等键，同次重试保留原键和原内容。
- 每一步同时保存用户反馈、接口结果与必要业务记录。密钥、Cookie、CSRF 令牌和原始个人信息不进入交付证据。

| 预期结果 | 审核只生成唯一有效企业资格，不自动公开申请资料；独立发布后渠道才可见。暂停后下一次专属请求被拒绝，私有资料不返回；普通身份业务仍可用，历史申请和询价可读，本人历史询价可关闭，关联渠道下线。恢复合作后专属能力恢复，渠道需人工重新发布。账户停用阻断全部受保护访问；恢复账户不使旧会话复活，重新登录也不恢复仍被暂停的合作。申请、询价、企业和历史全部保留，无他人企业数据泄露。 |
| 证据 | 各状态下同一会话的资源访问矩阵、公开渠道前后结果、企业和申请版本、文件拒绝结果、账户恢复后的新旧会话对照 |

| 证据 | 推荐列表与文章关联前后截图、引用登记和删除响应、PDF 内容散列及新旧标识结果、下线后的直接下载响应 |

### T-I-06 咨询、申请、询价共享同一个限流计数

| 关联依据 | FR-19、22、25；NFR-02；BR-06；TC-26；契约 3.1、6.2、7.1 |
| 优先级／方式 | 高；受控测试时钟＋真实路由的接口集成；所有请求均有合法凭据 |
| 前置条件与数据 | U1 是无申请的普通用户，U2 独立启用；两者共享写入计数均为 0；ADM 可即时审核；Q1 经销配置完整。业务写入均安排在同一个不足 10 分钟的时间窗，预置数据不计入该窗口 |
| 操作步骤 | 1. U1 合法提交 1 次申请，ADM 审核通过，保持 U1 身份；该用户已累计 1 次受限写请求。<br>2. U1 使用不同 UUID 成功创建 8 个合法咨询及 11 个 Q1×12 的询价，使累计为 20。<br>3. 第 21 次尝试创建咨询，第 22 次尝试创建询价；期间分别 GET 本人已有记录。<br>4. U2 同时提交一条合法普通咨询。<br>5. 将测试时钟推进至最后一次计数请求后 10 分 1 秒，再由 U1 使用新键提交合法咨询。 |
| 预期结果 | 前 20 次合法写入获准；ADM 审核不计入 U1 的用户写入桶。第 21、22 次分别来自不同模块但均返回 429 和可用等待提示，无新增咨询／询价及成功审计；不能通过切换业务入口绕过限制。GET 仍可读取；U2 不被 U1 的限流阻断。时间窗过后 U1 可再次提交。限流桶的具体时间窗实现及拒绝请求是否续计按已确认契约固定，不以反复失败请求延长等待作为本例假设。 |
| 证据 | 按时间排序的请求台账（身份、模块、键的脱敏标签、状态码、Retry-After）、业务新增数、两用户对照、测试时钟推进记录 |
