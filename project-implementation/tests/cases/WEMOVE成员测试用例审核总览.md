本轮交付是可执行的测试设计文档，尚未编写自动化测试程序。文中的“脚本”表示建议执行方式，依赖就绪后应将步骤实现为可重复脚本。真实支付、真实物流、邮件找回密码、正式经销订单、企业子账户等后续版本功能不列为本期成功用例。

## 3. 编号、优先级和记录粒度

- `FR` 表示功能需求，`BR` 表示业务规则，`NFR` 表示质量要求；原 `TC-01` 至 `TC-41` 是需求中的验收场景。
- `T-A-01` 等是本次展开后的成员用例编号，`T-I-01` 等是集成用例编号；不改写或挤占原 TC。一个 TC 可拆成多条用例，一条用例也可覆盖几个紧密相关要求。
- **高／中／低**表示测试执行次序及风险，高优先级主要关注权限、金额、库存、状态、重复、并发与持久化；它不等于 SRS 中 P0/P1/P2 的交付范围。全部在范围内的用例仍需执行。
- 带多组输入的用例是一组参数化测试，每个样本单独记录实际结果。例如数量为 0、1、99、100 是四个执行样本，不能只测 1 就给整组判定通过。本总览按用例编号计数，不把样本数算成独立用例数。
- 优先“高风险模块用例 → 对应集成链路 → 其余用例 → 全设备与性能检查”。同一交付候选版本完成全部必要验证后，再作整体验收判断。

## 5. 必须保留的客观判据

测试的“预期结果”相当于判卷标准，不能只写“功能正常”。以下统一判据来自 SRS，成员文档在各自场景中具体展开。

| 检查对象 | 判定方式 |
| --- | --- |
| 金额 | \(2990\times3+5900=14870\) 分；订单按服务端可信零售价计算。购物车跟随当前价，订单快照保留成交时信息，经销参考价不参与零售计价 |
| 库存 | \(S_{末}=S_{初}+\sum 入库+\sum 取消返还-\sum 出库调整-\sum 成功付款扣减\)，并且 \(S\geq0\)。加购、建待付款单、付款失败、发货／收货、询价／咨询不改变库存 |
| 重试与并发 | 幂等可理解为“同一张办理凭条再递交，仍只办一次”：检查业务记录、库存与退款的唯一效果。并发检查允许的合法终态，不预设哪个请求必须获胜；同步竞争与顺序重复分别记录 |
| 原子性与快照 | 事务是一组变更共同成功或共同撤回；注入失败后逐项核对余额、记录、购物车及历史，不能只看接口报错。快照保存“当时是什么”，当前状态决定“现在还能否操作” |
| 授权 | 认证回答“是谁”，授权还要回答“能否操作这条数据”。直接请求接口、换他人的记录 ID、重放旧会话、改客户端角色都须验证，不只检查按钮隐藏 |
| 读接口性能 | 单客户端、基线数据、预热后，商品列表／详情／本人订单各连续 20 次；每类至少 19 次在 1 秒内，不以平均值替代逐次原始耗时 |
| 页面性能 | 首页／商品列表／详情／购物车各加载 5 次；每页至少 4 次在 3 秒内显示主要数据并可操作；文件传输耗时另记 |
| 兼容与可用性 | 宽度 390、768、1440 px；Chrome 与 Safari 或 Edge 至少两种浏览器。覆盖 SRS 指定关键页面和表单，页面整体不横向溢出，后台宽表仅局部滚动；键盘焦点、标签和文本错误可识别 |
