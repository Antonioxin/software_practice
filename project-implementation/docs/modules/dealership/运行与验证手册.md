# 经销合作运行与验证手册

## 环境与迁移

沿用工程根目录的 Java 21、Maven 3.9+、Node.js 20+、npm 10+ 与 MySQL 8.0+ 环境。后端启动时 Flyway 自动执行 `V8__dealership_cooperation.sql`，新增申请、版本、审核、企业、渠道、询价明细和历史表，并写入两条已发布、一条未发布的独立测试渠道。

从仓库根目录运行：

```powershell
mvn -f project-implementation/apps/api/pom.xml spring-boot:run
```

另开终端：

```powershell
npm --prefix project-implementation/apps/web ci
npm --prefix project-implementation/apps/web run dev
```

## 页面入口

| 身份 | 页面 |
| --- | --- |
| 游客 | `/channels` |
| 启用普通用户 | `/account/dealer-application`、`/account/inquiries` |
| 有效经销商 | `/dealer/catalog`、`/account/inquiries/:id` |
| 管理员 | `/admin/dealer-applications`、`/admin/inquiries`、`/admin/companies`、`/admin/channels` |

## 建议闭环

1. 注册普通用户并登录，提交合作申请。
2. 用管理员账户登录，从合作审核队列打开当前版本并通过。
3. 普通用户刷新后确认派生身份为经销商，进入经销目录。
4. 选择至少一项商品并填写不低于 MOQ 的整数数量；可故意超过库存，确认仍能提交。
5. 管理员在询价详情填写公开回复和逐行参考价/交期。
6. 经销商查看回复并关闭；检查关闭后没有继续写入入口。
7. 管理员建立渠道草稿、明确发布；游客按地区查询。暂停关联企业后确认渠道消失，恢复合作后仍需人工发布。

## 自动化命令

```powershell
mvn -f project-implementation/apps/api/pom.xml test
npm --prefix project-implementation/apps/web run test -- --run
npm --prefix project-implementation/apps/web run build
```

`DealershipWorkflowIntegrationTest` 使用 H2 的 MySQL 兼容模式验证 HTTP 闭环，不执行 V8 的真实 MySQL DDL。正式合并前仍应在测试 MySQL 8 实例运行 Flyway、启动应用，并按成员 D 测试稿执行并发、故障注入、暂停和跨用户隔离场景。
