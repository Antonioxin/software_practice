# 零售交易运行与验证手册

## 1. 接入范围与实施参数

复用统一 Vue/Java 应用。`wemove.commerce` 与 `identity`、`catalog` 平级；D 的 `dealership` 根目录未改。FR-13—18 已提供购物车、预览建单、模拟付款、整单取消退款、模拟整单发货和本人收货。经销身份按零售价，管理员只管理订单。

- 购物车最多20行，每行1—99件；空车逻辑版本1。整车结算，无勾选项。
- 预览15分钟，数据库只保存令牌摘要；一次消费由唯一约束保护。建单不扣减或预占库存。
- 价格/商品/收货地址保存在订单快照；付款仍用快照价格，但核对当前可售和库存。运费、额外税费和优惠固定0。
- 地址省州选填，国家/城市为自由文本；名称按码点校验，电话标准化为可选加号及6—20位数字。没有接入外部地区库。
- C业务版本从1开始；A/B原0起始版本原样保留，前端不加减1。
- 新增迁移：V4幂等状态/兼容元数据、V5运营审计、V6交易表、V7大容量重放响应及库存来源索引。V1—V3未改；V3只在升级经过它时撤销旧登录会话。

完整请求与响应见 [OpenAPI](../../../contracts/openapi/commerce.yaml)。页面：`/cart`、`/checkout`、`/account/orders`、`/account/orders/:id`、`/admin/orders`、`/admin/orders/:id`。

## 2. 启动

安装 Java21、Maven3.9+、Node20+、npm10+、MySQL8。沿用 [身份手册](../identity/运行与验证手册.md) 的环境变量、管理员初始化和会话配置。以下命令从仓库根运行：

```powershell
npm --prefix project-implementation/apps/web ci
mvn -f project-implementation/apps/api/pom.xml spring-boot:run
npm --prefix project-implementation/apps/web run dev
```

默认前端5173，后端8080；先创建数据库并配置 `DB_URL/DB_USERNAME/DB_PASSWORD`。Hikari每个MySQL连接设置 `innodb_lock_wait_timeout=2`；`DB_CONNECTION_INIT_SQL`可覆盖用于测试，正式MySQL不要放宽而不复核并发预算。浏览器只连接同源 `/api` 代理，写请求包含Origin与CSRF。

迁移前停止旧服务、备份数据库，先在隔离副本验证升级；不与旧幂等写入实现混跑。不得改写已应用迁移或用删会话/清幂等表规避兼容。

## 3. 事务与恢复

公共 `IdempotencyExecutor` 必须在事务外调用；内部每次通过UnitOfWork开始完整事务。顺序为启用账户排他锁→幂等执行权→车头/订单→按UUID字符串排序逐项商品/库存→完整原流水及附属表/审计。账户锁保守串行化同账户命令；不同账户仍可并发，竞争订单和库存时由对应行锁保护。锁等待2秒，最多3次整事务尝试，耗尽返回409 REQUEST_IN_PROGRESS及Retry-After:2。

同账户同操作同键完成结果先于业务有效期/旧版本检查重放。当前实现不清理完成记录，至少满足24小时；预览消费约束和支付/退款永久唯一约束继续保护业务。响应保存为LONGTEXT以容纳多次模拟失败历史。执行中占位没有独立事务，业务失败时一并回滚。

旧A/B记录保留原operationId和摘要，schemaVersion=1。新入口按稳定操作族查该账户该键的所有记录；单条旧记录须匹配目标和旧摘要，多个旧目标碰撞统一拒绝新效果。检查碰撞清单：

```sql
SELECT BIN_TO_UUID(actor_id) AS actor_id,
       SUBSTRING_INDEX(operation_id, ':', 1) AS operation_family,
       BIN_TO_UUID(idempotency_key) AS request_key, COUNT(*) AS legacy_count
FROM idempotency_records
WHERE schema_version = 1
GROUP BY actor_id, SUBSTRING_INDEX(operation_id, ':', 1), idempotency_key
HAVING COUNT(*) > 1;
```

碰撞时查询原商品/订单/账户状态及原记录，人工核对；不任意挑选响应、不删旧记录后重做。旧记录适配停止旧版本后一次切换。

前端sessionStorage按账户保存待恢复操作、原路径、原体和键。断网、非明确5xx、REQUEST_IN_PROGRESS显示“结果暂未确认”；重试保持原请求。完成后重新GET当前订单。退出或账户失效清除；超过24小时不自动重发，应先查询业务记录，必要时退出后重新登录再手工确认新操作。PATCH/DELETE未知结果先GET购物车核对绝对数量与版本，不自动用新版本重复写。

## 4. 审计与 F 端口

`wemove.operations.audit.DatabaseAuditAdapter` 是正式持久适配器，由F职责域所有，参与调用方事务；失败导致订单效果回滚。公共AuditEvent增加requestId/changeSummary，旧调用方有兼容构造器。`LoggingAuditAdapter` 不再注册为Spring Bean，不能替代正式审计。

`OrdersPort` 只返回本人订单最小引用，取消/完成历史也可引用；非本人与不存在同404。`CommerceMetricsPort`要求已有事务，F先做管理员授权并在同一只读数据库快照内调用，不由C另开事务。净额为区间内成功付款订单减这些订单截至快照的全部已完成退款，精确十进制整数分字符串；不是区间收款减区间退款。F统一生成asOf。F工单/仪表盘/UI尚未接入，端口通过不代表TC-37全组通过。

## 5. 自动化验证

```powershell
mvn -f project-implementation/apps/api/pom.xml verify
npm --prefix project-implementation/apps/web run test
npm --prefix project-implementation/apps/web run build
```

默认Maven保留H2装配检查及规则测试；真实MySQL测试显式启用，否则跳过。仅对独立测试实例运行，下例端口13316应指向自己新建的隔离MySQL，数据库名以commerce_test开头：

```powershell
$env:MYSQL_TEST_URL='jdbc:mysql://127.0.0.1:13316/commerce_test?allowPublicKeyRetrieval=true&useSSL=false&serverTimezone=UTC'
$env:MYSQL_TEST_PASSWORD='<隔离实例root密码>'
mvn -f project-implementation/apps/api/pom.xml verify
```

`CommerceMySqlTest`真正启用Flyway与Hibernate validate，创建合成用户/商品并通过服务执行交易；使用独立线程/连接、CyclicBarrier并发，每种主要竞争重复10轮。故障仅由测试替换不可配置的TransactionProbe触发，生产Bean无行为，没有HTTP故障开关；持久审计仍为真实数据库适配器。

`CommerceMigrationMySqlTest`需隔离实例的建库权限；新建独立 `commerce_upgrade_<版本>_<随机标识>` 数据库并保留以便检查，验证V2/V3升级、V1/V2校验和、业务/旧幂等记录及会话撤销。绝不清空传入数据库。真实MySQL tests与H2结果分别记录。

HTTP冒烟需已运行的测试应用与管理员，脚本创建合成成人用户及两单，净消耗测试商品1件库存：

```powershell
./project-implementation/scripts/smoke/commerce-api.ps1 `
  -BaseUrl http://localhost:8080 -Origin http://localhost:5173 `
  -AdminEmail '<测试管理员邮箱>' -AdminPassword '<测试密码>'
```

默认使用V2种子的软质投环组；若库存不足，先用后台正规库存调整或传入其他可售ProductId。脚本不应指向业务数据库，不采集真实付款信息或真实收货地址。测试证据与未执行边界见 [验证记录](验证记录.md) 和 [验收追踪](角色C验收追踪.md)。
