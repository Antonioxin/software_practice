## 本轮发现与修复

- MySQL不接受最初V6中跨列的列级CHECK：改为适用的约束后在新库重新迁移；未篡改已成功迁移的校验和。
- 幂等占位保存使用merge返回的受管实例，确保完成状态与响应被持久化。
- 支付/归还先取得完整排序商品锁，再读取原流水，避免陈旧快照与部分集合误判。
- 多次付款失败历史可能超过原响应列容量，V7扩大为LONGTEXT。
- 重复运行统计测试受到旧合成付款污染，测试区间改为已存在付款最大时间之后，隔离各轮数据。
- HTTP冒烟无请求体时显式声明JSON；不支持的媒体类型返回415。
- 页面补充商品不可售时的原请求恢复入口、表单校验保留地址、订单标题及中等宽度导航布局。
- Maven打包曾因本轮运行中的JAR被Windows锁定而失败；停止该进程后完整verify通过，后续浏览器使用复制的review JAR。
- 最终前端构建发现格式化后的列表多语句事件无法被Vue解析，已改成具名处理函数；重新构建通过，Edge列表与筛选/刷新实测正常。
- 复用旧测试库浏览目录时，直接SQL创建的最小商品缺少分类导致展示失败；补齐新测试夹具的分类、年龄、玩法、场景、概要和图片字段。旧库数据保留不作为演示目录；已单独检查合法种子商品的目录与详情。运行浏览器演示宜使用新迁移的独立库，不复用历史自动化夹具库。
