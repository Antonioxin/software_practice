# 角色 C 前端风格统一修改方案

日期：2026-09-06。状态：修改方案，尚未实施。依据当前B商品前台/后台源码及[关键功能走查](../../verification/commerce/关键功能走查-20260906/走查报告.md)。

## 1. 目标与参照

让“商品 → 购物车 → 结算 → 我的订单”呈现为同一个产品中的连续流程；管理员订单与B商品管理保持同一后台规范。此次重做页面布局、视觉层级、组件与交互反馈，保留已验证的业务命令和数据边界。

| 参照 | 复用内容 | C对应位置 |
| --- | --- | --- |
| PublicShell、ProductsPage、ProductDetailPage | 浅色品牌导航、米纸底色、土红眉题、衬线标题、商品图形、深绿购买区域 | 购物车、结算、用户订单列表/详情 |
| SiteShell、AdminProductsPage、AdminProductEditorPage | 深绿后台导航、标题区域、筛选表单、状态标签、紧凑表格、确认弹窗 | 管理员订单列表/详情 |
| styles.css现有变量和控件 | 主次/危险按钮、field/field-pair、错误提示、焦点样式 | 全部交易页面 |
| ProductArtwork | 同一商品的名称/SKU图形占位 | 购物车、结算、订单详情商品行 |

不复制商品首页420px的宣传首屏到交易页。交易页保留B的字体、颜色、构图关系，使用更紧凑的页头，把商品、金额与下一步操作放在前面。

## 2. 统一视觉规范

| 项目 | 拟采用规范 |
| --- | --- |
| 配色 | 使用现有--ink、--muted、--paper、--canvas、--line、--green、--green-dark、--clay、--gold、--danger；消费者页面底色跟随PublicShell的#f1ecdf |
| 字体 | 沿用DM Sans / Noto Sans SC正文；标题沿用Playfair Display / Noto Sans SC组合；标题建议32—44px，正文14—16px，辅助信息12—13px |
| 容器 | 消费者页面与B详情页对齐：最大1320px，桌面左右24px；后台沿用admin-main，去掉C额外1100px嵌套限宽造成的左侧堆积 |
| 间距 | 基于8/16/24/32/48px层次组织；页头约32—48px上下间距，不用大面积空白撑页面 |
| 表面 | 米纸底、细线分区、小圆角；只为金额摘要、状态和必要表单区域提供面板，不再每段内容套一张白色圆角卡片 |
| 按钮 | 沿用primary/secondary/danger-button；深绿主按钮使用浅色字，深绿金额区域可用B购买面板的土黄按钮；删除C对所有button强制设置颜色的规则 |
| 链接 | 正文链接可下划线；导航、商品行入口、按钮式链接不统一加下划线 |
| 状态 | 文字标签配合颜色：待付款、待发货、已发货、已完成、已取消；不能仅靠颜色区别 |
| 提示 | “模拟交易”用一条简短说明或标签；业务版本、幂等键不出现在普通购买流程。模拟流水号放在详情区次要位置 |

## 3. 页面逐项调整

### 购物车 /cart

- 上方为返回商品入口、眉题、购物车标题和商品行数。
- 桌面采用“商品清单 + 约320—360px金额摘要”两列。商品清单有图形缩略图、名称/SKU、单价、数量控件、小计、移除入口；使用分隔线组织。
- 右侧沿用B深绿购买区域：商品金额、零运费/额外税费/优惠、明显的总价和“前往结算”。摘要适度吸顶，不能遮住页脚。
- 数量保存时禁用该次相关写入和结算入口，明确显示更新中；失败后展示重新读取的数量与解释。
- 无效商品、价格变化就近提示在商品行，不只在页面顶部报错。
- 清空为次级动作；空车展示简洁图形、说明及“继续选购”，不保留空摘要。

### 结算 /checkout

- 简洁流程提示“购物车 → 确认订单 → 订单结果”，只说明实际存在的步骤。
- 左侧地址表单，右侧商品及金额摘要。收件人/电话并排，国家/省州/城市合理分组，详细地址和备注整行；手机端单列。
- 商品图形、名称、数量和成交价与B详情视觉一致。预览有效期用辅助文字显示，过期才突出提示并提供重新预览。
- 错误摘要与字段级提示联动，设置aria-invalid和aria-describedby；提交失败将焦点移至错误摘要或首个无效字段，让用户无需向上寻找错误。
- 保留已填地址。提交区明确“创建模拟订单”，失败与重试状态可读。
- 原请求待恢复时显示独立提示和“使用原请求重试/查看订单”，不能把已固定的请求重新变成可编辑提交。

### 用户订单列表 /account/orders

- 从SiteShell切换到PublicShell，让购物与订单导航、标志、页脚保持一致。
- 使用紧凑页头、状态筛选和结果数量。每行突出订单号、创建时间、状态、金额与查看入口，避免大块稀疏白卡片。
- 当前列表API只提供摘要：本轮不凭空增加商品缩略图、商品名称、件数或各状态数量，不为每行额外请求详情。
- 加载中、空结果、加载失败和重试分别呈现；页数与总数有一致的分页区域。

### 用户订单详情 /account/orders/:id

- 同样使用PublicShell，页头含返回订单、订单号、时间和状态标签。
- 桌面主体左侧为商品快照、地址/物流和交易记录；右侧为状态说明、金额及当前可执行操作。首屏能找到状态、总额与下一步。
- 商品快照用与购物车一致的商品行；地址按标签和值排版，避免大块空白。
- 订单历史做紧凑时间线。取消作为独立终止结果，不伪装为“完成”；付款失败作为事件保留，不推进状态进度。
- 付款、取消、收货确认沿用现有Element Plus对话框能力，配B按钮和表单；取消说明退款/库存后果。模拟付款仍可选择失败用于课程演示。
- 模拟流水号保留可查看，但降低视觉权重；无可用动作时移除整个操作容器，消除已完成/取消后的空白卡片。

### 管理员订单列表 /admin/orders

- 保留SiteShell，沿用B商品后台的标题、筛选面板、表格、行操作、分页布局。
- 筛选包含现有状态和创建时间区间，配查询/重置，起止时间说明清楚。
- 表格列使用接口已有字段：订单号、创建时间、状态、金额、查看。金额右对齐；不虚构买家信息、待发货总数或销售统计。
- 小屏转换为带字段标签的紧凑记录，或在表格容器内滚动；整页不能横向溢出。

### 管理员订单详情 /admin/orders/:id

- 保留后台外壳，使用B编辑页的分区标题和详情信息密度。
- 顶部清晰显示状态/订单号；主体商品与地址信息，侧栏显示金额及发货/取消入口。
- 发货表单沿用B库存调整弹窗的尺寸、字段和底部主次按钮规范。
- 历史与付款退款仍可核对；权限与操作可用性以allowedActions为准，不由页面自行猜测。

## 4. 组件及文件调整

先复用现有PublicShell、SiteShell、ProductArtwork、按钮/表单基础类和已安装的ElDialog，不引入新UI库或外部图片服务。

拟将交易领域的重复展示抽为小组件：OrderStatusBadge、CommerceItemRow、PriceSummary、OrderTimeline、OrderActionDialog。职责分别为状态、商品行、金额、历史与确认操作；按实际复用情况抽取，避免只为单个小段落建立组件。

| 文件范围 | 修改内容 |
| --- | --- |
| features/commerce/style.css | 删除覆盖基础按钮/输入/链接的宽泛规则；改为布局和交易组件样式，引用共享变量 |
| pages/commerce/CartPage.vue、CheckoutPage.vue | 两列结构、商品行、金额摘要、字段错误及提交状态 |
| pages/commerce/OrdersPage.vue及管理员包装页 | 用户/后台分别选择合适外壳和列表呈现，共享查询逻辑 |
| pages/commerce/OrderDetailPage.vue及管理员包装页 | 详情分区、操作对话框、时间线、无操作时不渲染空面板 |
| features/commerce/components/ | 必要的领域展示组件 |
| styles.css、PublicShell、SiteShell | 仅在复用确有需要时作小范围兼容调整；同时复查B页面，避免被C样式污染 |
| docs/verification/commerce/ | 新旧同尺寸对照截图、关键操作回归与问题关闭记录 |

API、支付/退款语义、价格快照、购物车版本、幂等重放、会话权限与数据库迁移不因视觉改造而调整。列表若将来需要买家/商品摘要，应另行讨论契约扩展。

## 5. 实施顺序

1. **统一基础与购物车样板**：落实按钮/表单/间距，完成购物车桌面与手机布局；与B商品详情并排核对后，作为其余页面的尺度基准。
2. **完成消费者闭环**：结算、用户订单列表、用户详情；保留错误和未知结果恢复，实走建单—付款—取消退款、发货—收货。
3. **统一后台**：订单列表和详情对照B商品管理；复查管理员操作、筛选、弹窗与窄屏。
4. **回归与证据**：修复视觉和交互缺陷，完成各断点截图与前端检查，更新验收记录。每阶段都交付可运行页面，不只修改静态效果图。

## 6. 验收标准

- 消费者四页使用同一浅色导航/品牌/页脚；后台两页沿用B后台。颜色、按钮、输入框、字体和间距具有直接可见的一致性。
- 1440×900、768×1024、390×844检查：无整页横向溢出、无重叠、无文字裁切；窄屏优先保证状态、金额、操作清楚。平板可转单列，不勉强塞两列。
- 主按钮文字在默认、悬停、焦点与禁用状态均可辨认；普通文字对比度目标至少4.5:1，控件焦点可见。触控目标原则上不小于44px。
- 桌面首屏可识别当前任务和关键金额/状态；不要求长表单强塞首屏，但提交失败必须把错误带到用户可见位置。
- 已完成/已取消/无管理员动作的订单不存在空操作面板；订单号与流水号换行不会撑破页面。
- 加载、空、错误、不可售、提交中、未知结果与成功状态都有明确内容，禁止把失败包装成成功。
- 完整回归本轮走查的加车改量/移除清空、地址校验、建单、模拟失败/成功、退款、发货收货、筛选、终态限制；补查双击提交及原请求恢复，确认重构没有重复命令或丢失原键。
- 运行前端Vitest及构建；对新增复杂交互补必要组件测试。若未改后端，不以重跑后端测试替代前端视觉验收。
- 同时复查B商品列表、详情、管理员商品列表/编辑/库存弹窗，防止共享CSS和外壳出现回归。
- 截图在页面渲染稳定后拍摄，每张亲自核对状态与构图；长页用明确的顶部/下部分屏，避免拼接异常。报告分别记录功能、视觉、未执行项，正式26/159条仍由团队逐项审核。
