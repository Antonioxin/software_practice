# 站点、内容与文件模块

成员 E 的实现接入共享 Vue 3 前端与 Spring Boot 后端，对应 FR-01、FR-02、FR-06、FR-07、FR-28、FR-29。首页与导航沿用原有设计，内容由数据库维护。

## 操作入口

| 页面 | 地址 | 功能 |
| --- | --- | --- |
| 内容管理 | `/admin/content` | 文章、FAQ、Banner 的草稿、编辑、发布、下线；关键词与状态筛选 |
| 品牌与首页 | `/admin/content/settings` | 品牌介绍、联系方式、说明正文及版本、按序推荐商品和精选文章 |
| 文件与媒体 | `/admin/files` | PDF 上传、属性与可见范围维护、替换当前版本、发布下线；图片媒体库与引用数量 |
| 玩法灵感 | `/articles`、`/articles/:id` | 已发布文章、独立地址、页面标题及描述、正文与关联商品 |
| 常见问题 | `/faq` | 按关键词、分类和商品筛选，可展开答案 |
| 下载中心 | `/downloads` | 按类型、关键词和商品筛选，只显示当前身份可读的已发布资料 |
| 品牌及说明 | `/about`、`/terms`、`/privacy` | 展示后台维护的信息；注册同意版本与说明页面共用数据源 |

管理员登录后，工作台左侧可直接进入三个管理页面。普通访客可从主导航“玩法灵感”、首页“内容与帮助”及页脚进入公开内容。

## 内容发布流程

1. 创建文章或 FAQ 草稿，填写文字、分类、排序和关联商品。文章支持可视化文字块与图文块、左右图文、通栏图片、图注及实时预览，操作见[文章图文排版](文章图文排版.md)。
2. 保存后点击“发布”。发布时服务端检查必要正文、关联商品和媒体；Banner 必须设置有效图片、标题和目标链接。
3. 重新访问公开网站即可看到发布结果，无需重新构建前端。下线后保留管理记录，公开列表和旧文章地址均不再返回内容。

正文经服务端 Jsoup 白名单清洗，前端再以受控节点渲染。脚本、事件属性、嵌入页面、任意样式与脚本链接不会执行。文章可复用六张受控商品玩法插图；上传的正文图片会自动登记媒体引用，在公开内容中使用后才允许游客通过媒体接口读取。正文配图与独立封面／补充图库分开管理，移除图文块后不会残留为尾部配图。

后台保存采用版本校验：提交 `expectedVersion` 必须等于服务器当前版本，相当于“我修改的是刚才看到的那一版”。两位管理员同时编辑时，后提交者得到 `409 VERSION_CONFLICT`，不会静默覆盖先提交的修改。创建和发布命令使用幂等键，同一请求重试不会重复创建或重复执行。

## 文件与媒体规则

- 图片支持 JPEG、PNG、WebP，最大 5 MiB；PDF 最大 10 MiB。服务端校验文件扩展名、声明 MIME 和实际可解码内容，拒绝损坏图片、伪装文件及加密/无页面 PDF。
- 媒体库可复制图片 ID，在商品编辑页粘贴为主图或附图；文章、Banner、品牌设置可直接选择图片。现有六组受控本地商品素材继续可用，新媒体优先显示。
- 图片删除保护所有登记引用，包括草稿。先在引用内容或商品中移除/替换图片，再删除；下线内容只撤销公开访问，不自动解除引用。
- 资料可见范围为 `PUBLIC`（所有访客）、`DEALER`（有效经销商）、`INTERNAL`（管理员）。普通列表与详情不返回无权读取资料的标题或下载元数据。
- `fileId` 是资料的稳定身份；`downloadId` 是当前文件版本。替换文件保持前者，更新后者；旧下载地址立即返回 404。下线后所有身份的业务下载都不可用。
- 二进制保存在独立 `content_binaries` 表，元数据列表不会加载文件正文。替换、新文件字节、版本与审计在同一个数据库事务提交，失败时旧版本保持有效。私有文件没有可绕过服务端的静态地址。
- 每次下载重新检查账户与当前企业合作状态。合作暂停后，即使仍保留旧页面或旧下载链接，也无法再次取得经销商文件。已下载到本地的副本不属于可撤回范围。

## 运行与验证

沿用[工程入口](../../../README.md)启动方式。后端启动自动执行 Flyway `V10__content_management.sql` 和 `V11__content_assets.sql`，创建内容、设置、文件、媒体及引用表。V10 提供文章、FAQ 与品牌说明的初始数据；文件需通过后台实际上传。

从仓库根目录执行：

```bash
npm --prefix project-implementation/apps/web run test
npm --prefix project-implementation/apps/web run build
mvn -f project-implementation/apps/api/pom.xml verify
```

内容与文件的真实 HTTP 冒烟脚本仅使用 Python 标准库，要求已启动后端及独立测试数据库。它会创建测试文章、图片和 PDF，验证发布、下线、替换、权限与引用保护，最终留下下线的文章与资料记录。先在当前终端设置 `CONTENT_SMOKE_ADMIN_PASSWORD`（不要提交到版本库），再执行：

```bash
python3 project-implementation/scripts/smoke/content-api.py \
  --base-url http://localhost:8080/api/v1 \
  --admin-email content-admin@example.test \
  --allow-test-writes
```

无需后端时，可访问 `/admin/content?preview=1&role=admin`、`/articles?preview=1`、`/downloads?preview=1`。预览使用独立样例数据，发布、上传、下载真实文件均不会执行；预览通过不能代替真实业务验证。
