# 媒体与下载资料管理

## 范围与入口

本实现对应 FR-07、FR-29，扩展共享后端 `wemove.content.assets`，与内容及商品发布使用同一事务。完整 HTTP 字段见 [files.yaml](../../../contracts/openapi/files.yaml)。

- `/downloads`：按标题、资料类型、关联商品查询当前可见资料。
- `/admin/files`：上传 PDF、编辑资料信息与可见范围、替换当前版本、发布和下线。
- `/admin/files?tab=media`：上传 JPEG、PNG、WebP，查看引用数量，删除未引用素材。
- 后台资料初始状态为 `DRAFT`，发布后成为 `PUBLISHED`；下线后为 `OFFLINE`。只有已发布资料可下载，管理员也遵循该状态限制。

## 权限与下载标识

| 可见级别 | 游客／普通用户 | 有效经销商 | 管理员 |
| --- | --- | --- | --- |
| `PUBLIC` | 可读 | 可读 | 可读 |
| `DEALER` | 不可读 | 可读 | 可读 |
| `INTERNAL` | 不可读 | 不可读 | 可读 |

列表和详情先校验可见性，无权查看的标题、版本说明等不返回。每次下载重新读取账户状态和当前经销合作资格；暂停合作后，原会话中的旧链接也不能继续下载。不存在、无权访问、草稿／下线资料和旧下载标识统一返回通用 404，不泄露存储路径。

逻辑 `fileId` 用于稳定关联商品和资料。替换 PDF 保留 `fileId`，重新生成 `downloadId`；旧 `downloadId` 随事务提交立即失效。资料编辑、替换、发布／下线均检查 `expectedVersion`，过期编辑返回 `409 VERSION_CONFLICT`。发布／下线要求 `Idempotency-Key`，同键同请求重放不会重复产生业务效果。

## 上传校验和持久化

- 图片最多 5 MiB，实际解码支持 JPEG、PNG、WebP；解码尺寸最多 4000 万像素。
- PDF 最多 10 MiB，由 PDFBox 解析，拒绝损坏、零页和加密文档。
- 扩展名、声明 MIME 与实际格式必须一致；文件名去掉路径片段和控制字符。
- 所有二进制响应使用正确 MIME、`Cache-Control: no-store`、`X-Content-Type-Options: nosniff`。PDF 使用安全 UTF-8 文件名并作为附件下载。
- `content_assets` 和 `content_files` 只存元数据，`content_binaries` 独立存放 `LONGBLOB`，资料列表不会加载 PDF 正文。上传内容不会写入公开静态目录。
- 文件、元数据、当前版本切换和审计属于同一数据库事务。数据库或审计失败会一起回滚，旧 PDF 保持可用；不会出现先删旧文件而数据库回滚后链接断开的情况。
- 当前范围不提供历史版本恢复，替换成功后清除旧版本二进制。管理端不自动重试 multipart 上传；结果未知时先查询资料库。

此存储方案适合课程项目的小规模文件管理，后续迁移对象存储需单独设计暂存、数据库指针切换与孤立对象清理，不能简单把磁盘写入视作数据库事务。

## 素材引用与商品兼容

内容／商品通过 `ContentAssetsPort.replaceReferences` 在自身事务里同步更新引用。公开媒体入口只允许当前存在已发布引用的素材；管理员可预览有效草稿素材。所有引用（包含草稿）均阻止删除，返回 `409 ASSET_IN_USE`。应先在引用方移除或替换图片，单纯下线不会解除草稿引用保护。

引用更新和删除按同一组媒体行加锁，媒体 ID 排序后依次获取锁。商品创建、编辑、发布与下架均已接入该端口。

旧商品在媒体库建立前保存的非 UUID 图片键允许在原商品上沿用；新增图片须为有效素材 UUID，或六个受控内置图片键：`product-balance-stones`、`product-rainbow-arch`、`product-ring-toss`、`product-team-board`、`product-forest-kit`、`product-skip-rope`。任意新字符串不会被当作有效图片接受；内置静态素材不属于可删除的上传素材。

## 验证与依赖修复

新增测试位于 `apps/api/src/test/java/wemove/content/assets/`：

- `AssetRulesTest`：真实 PDF、PNG、WebP 解码、安全文件名、伪装类型、损坏内容和超限图片，以及 Unicode 码点长度边界。
- `AssetsWorkflowIntegrationTest`：HTTP 上传和权限矩阵、审批／暂停合作后的同会话下载、旧版本失效、下线、版本冲突、权限变化审计、引用保护、商品绑定，以及审计失败时二进制替换的事务回滚。

本次执行结果：`AssetRulesTest` 5 项通过、`AssetsWorkflowIntegrationTest` 4 项通过，另回归执行 `DealershipWorkflowIntegrationTest` 1 项通过，均无失败或跳过。完整权限验证暴露原经销商暂停路径的 HQL 时间类型错误：`CURRENT_TIMESTAMP` 为 `Timestamp`，无法赋给实体 `Instant`；现改为传入当前业务时间参数，使合作暂停及其渠道下线能正常提交。

可从仓库根目录执行：

```bash
mvn -f project-implementation/apps/api/pom.xml \
  -Dtest=AssetRulesTest,AssetsWorkflowIntegrationTest,DealershipWorkflowIntegrationTest test
```

本机沙箱不允许 Mockito 的 JVM 自动附加；验证时使用已缓存 Mockito JAR 的显式 `-javaagent` 参数。此参数是本机测试环境的运行方式，不写入项目依赖配置。上述集成测试使用独立 H2 内存数据库；MySQL 迁移与实际服务器验证需结合共享模块验证记录查看。自动测试结果不等于课程验收用例已经全部执行。
