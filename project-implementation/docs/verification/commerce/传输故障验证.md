# 浏览器传输故障验证

执行日期2026-09-06，Microsoft Edge，Vite15173 → 本地故障代理18086 → 复制的review JAR18087 → 隔离MySQL13316/commerce_test2。账户为合成commerce-browser@example.test。两次均从商品详情加车并填写结算表单，点击创建后看到“结果暂未确认”和“使用原请求重试”。

| 场景 | 原请求键 | 故障后SQL核对 | 原请求重试后SQL核对 |
| --- | --- | --- | --- |
| 响应丢失 | 4ad35107-d51c-4467-8447-cc1ea0ba6882 | 代理读完服务端201后断开；账户订单数从2到3 | 订单仍3；COMPLETED，返回dc333295-ff59-4ad9-bbd3-decc7a67edd3 |

代理实测输出：

```json
{"mode":"response-lost","path":"/api/v1/orders","key":"4ad35107-d51c-4467-8447-cc1ea0ba6882","upstreamStatus":201}
{"mode":"request-not-arrived","path":"/api/v1/orders","key":"9711e1cf-9406-4942-8b9b-669eee1848c3"}
```

SQL按账户关联commerce_orders计数，并按UUID_TO_BIN(原键)读取idempotency_records的execution_state与response_json中的id。故障订单保持待付款，不发生库存扣减。请求未到达截图第一次抓取超时，重新抓取成功后才点击重试，未把截图工具失败计为产品缺陷。

复现工具为[commerce-fault-proxy.mjs](../../../scripts/smoke/commerce-fault-proxy.mjs)。显式设置COMMERCE_FAULT_PROXY_ENABLED=isolated-test、COMMERCE_FAULT_CONTROL为绝对JSON文件路径、COMMERCE_FAULT_UPSTREAM为本地服务地址；Vite的VITE_API_PROXY_TARGET指向代理。每次写入上表mode及path的JSON控制文件，匹配的POST消费文件，仅阻断一次；下一次原请求正常转发。代理仅用于隔离测试，不属于应用服务或部署入口。
