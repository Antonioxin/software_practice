- 交易数据：走查内通过 C 模块公开接口完成加购 → 结算预览 → 建单 → 模拟支付，产出 1 笔已付款订单（软质投环组 ×1，¥129.00），用于 AFTER_SALES 工单关联。
- 所有写操作携带会话 Cookie + `X-CSRF-Token` + `Origin` + `Idempotency-Key`（每次写前重新获取 CSRF）。

## 证据说明与边界

- 本轮为 **API 级**走查：覆盖后端行为、状态机、权限与数据一致性；未包含浏览器界面截图。前端页面（/contact、/account/tickets、/admin/tickets、/admin、/admin/audit-logs）已有单测与构建覆盖，浏览器点击走查建议在合并前由成员自行补充。
- 走查脚本最初两次调用（注册缺字段、下单/支付复用过期令牌）分别返回 422 VALIDATION_ERROR 与 400 MALFORMED_REQUEST，属预期校验与脚本侧失误，修正后成功；未观察到应用侧异常。
- 限流（429）、版本冲突（409 VERSION_CONFLICT）、幂等重放、审计失败回滚等边界在 `SupportMySqlTest`（真实 MySQL）已覆盖，本轮不在开发库重复触发，避免污染计数桶。
- 走查时迁移文件名为 `V8__support_tickets.sql`；2026-09-07 因 D 的经销合作分支已占用 V8，F 的迁移改号为 `V9__support_tickets.sql`（内容零改动），本地测试库已按 V9 重建并复跑通过。
